### ステージ 4: 上下反転発覚 → MediaTexture flipY 修正

user 実機で preview を確認 → **写真が上下反転して表示**。

**原因特定**:
- `packages/film-lab-renderer/src/webgpu/shaders/fullscreen.vert.wgsl.ts`: NDC y=+1 → `uvRaw.y = y*0.5+0.5 = 1.0`、`uv.y = 1.0` が top of screen
- `packages/film-lab-renderer/src/webgpu/MediaTexture.ts:38/66`: `copyExternalImageToTexture({source, flipY: false})` → texture row 0 = bitmap top
- UV(0,0) = texture top = bitmap top、UV(0,1) = texture bottom = bitmap bottom
- top of screen が UV.y=1.0 → bitmap bottom をサンプリング → **上下反転**

**WebGL 経路で顕在化しなかった理由**: THREE.js Texture デフォルト `flipY: true` が WebGL texImage2D で UNPACK_FLIP_Y_WEBGL を立てていたため、WebGL UV convention と整合していた。WebGPU copyExternalImageToTexture はこの自動処理を持たない。

**Fix**:

```typescript
// packages/film-lab-renderer/src/webgpu/MediaTexture.ts (lines ~59, 93)
device.queue.copyExternalImageToTexture(
  { source: bitmap, flipY: true },  // ← false から true に
  { texture },
  { width: bitmap.width, height: bitmap.height },
);
```

`fromImageBitmap` / `fromVideoElement` 両方変更。JSDoc に Y orientation 解説追記。

**注記**: この fix は **本 chat で先行実装** していたが、並列 codex agent の commit `3e205386` が同値を含む上位コードに取り込んだため、本 chat 後半の working tree diff には現れなくなった。結果として現行 HEAD `f67e0702` の挙動に正しく反映されている。

### ステージ 5: Glass Morphism 不作動 → captureStream 方式へ全面書き換え

上下反転が直ると今度は **パラメータパネル(右側の編集コントロール)の背後 blur が効いていない** ことが判明。

**段階的試行**:

#### 試行 A: `::before` 疑似要素の `backdrop-filter`

```css
.fl-card.fl-card-muted.fl-card--frost.fl-card--frost-webgl-backdrop::before {
  background: linear-gradient(...);
  backdrop-filter: blur(28px) saturate(1.2) brightness(0.92);
}
```

→ **効かず**。背後の WebGPU canvas が blur されない。

#### 試行 B: outer 要素の `backdrop-filter`

`::before` から親要素へ移動:

```css
.fl-card.fl-card-muted.fl-card--frost.fl-card--frost-webgl-backdrop {
  background: linear-gradient(...);
  backdrop-filter: blur(32px) saturate(1.22) brightness(0.92);
}
```

→ **同じく効かず**。

#### 原因究明

元コード `FilmLabWebglPanelBackdrop.tsx` は `ctx.drawImage(webgpuCanvas, sx, sy, sw, sh, 0, 0, destW, destH)` を毎 RAF で叩いて 2D canvas に pixel copy し、CSS `filter: blur(22px)` で glass 化する設計だった。しかし:

- **Chromium は WebGPU accelerated canvas を別 compositor layer で合成する**
- `ctx.drawImage(webgpuCanvas)` は **silent failure**(例外なし、空 pixel 返す)
- CSS `backdrop-filter` も同 layer の pixel を読めない
- 両方の経路が失敗 → backdrop canvas 透明 → CSS backdrop-filter も空振り → 素の preview が透ける

詳細は §11 Chromium Compositor Theory 参照。

#### 試行 C: `canvas.captureStream()` + `<video>` srcObject

```typescript
// packages/film-lab-ui/src/FilmLabWebglPanelBackdrop.tsx
const stream = src.captureStream(30);
video.srcObject = stream;
```

→ **✅ 効く**。

**理由**: `<video>` 要素は通常の DOM 合成レイヤーで描画されるため、WebGPU accelerated canvas の compositor boundary 問題に引っかからない。captureStream は canvas を MediaStream 化(30fps)、video にフレームが供給され、video 要素に CSS `filter: blur()` がそのまま効く。

初期 param `blur(28px) saturate(1.28) brightness(0.78)` + `transform: scale(1.18)` で visual 確認 → user feedback「若干強い」。

## 4. Fix #1 — GpuContext spec compliance

### Root cause

```typescript
// 修正前 (packages/film-lab-renderer/src/webgpu/GpuContext.ts:73-80)
context.configure({
  device,
  format: "rgba8unorm-srgb",  // ← WebGPU spec 違反
  alphaMode: "opaque",
  colorSpace: "srgb",
  usage: GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.COPY_SRC,
});
```

WebGPU spec (MDN / WebGPU W3C CR): `GPUCanvasContext.configure()` の `format` は `bgra8unorm` / `rgba8unorm` / `rgba16float` のみ。sRGB variant は:
- texture の `createTexture({format: "rgba8unorm-srgb"})` → OK(texture format として sRGB 許容)
- canvas の `configure({format: ...})` → NG
- canvas の `configure({format: "rgba8unorm", viewFormats: ["rgba8unorm-srgb"]})` + `getCurrentTexture().createView({format: "rgba8unorm-srgb"})` → これが canonical

### Fix (patch)

```typescript
// 修正後
context.configure({
  device,
  format: "rgba8unorm",                    // ← spec 準拠
  viewFormats: ["rgba8unorm-srgb"],        // ← sRGB view 宣言
  alphaMode: "opaque",
  colorSpace: "srgb",
  usage: GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.COPY_SRC,
});
```

```typescript
// 修正前 (line 100-102)
getCurrentTextureView(): GPUTextureView {
  return this.context.getCurrentTexture().createView();
}

// 修正後
getCurrentTextureView(): GPUTextureView {
  return this.context
    .getCurrentTexture()
    .createView({ format: "rgba8unorm-srgb" });
}
```

### Effect

## 7. Fix #4 — Preview 上下反転 (MediaTexture flipY)

### Root cause 再掲

WebGPU texture convention (MDN / W3C):
- `createTexture` → row 0 = top-left
- `getCurrentTexture().createView({format: "rgba8unorm-srgb"})` → 同じ
- UV(0,0) = top-left、UV(0,1) = bottom-left (Y 増加で下)

vertex shader の fullscreen triangle:
```wgsl
let x = f32(((vi << 1u) & 2u)) * 2.0 - 1.0;
let y = f32((vi & 2u)) * 2.0 - 1.0;
let uvRaw = vec2f(x * 0.5 + 0.5, y * 0.5 + 0.5);
let uv = vec2f(uvRaw.x, mix(uvRaw.y, 1.0 - uvRaw.y, uFlags.flipY));
```

- NDC y=+1 (top of screen) → `uvRaw.y = +1 * 0.5 + 0.5 = 1.0`
- `uFlags.flipY` default = 0 → `uv.y = uvRaw.y = 1.0`

`copyExternalImageToTexture({flipY: false})`:
- texture row 0 = bitmap row 0 (bitmap top)
- sample at UV(0, 1.0) = texture bottom = bitmap bottom

結果: **top of screen に bitmap bottom が描画** → **上下反転**。

### なぜ WebGL で発覚しなかったか

THREE.js `THREE.Texture` のデフォルト `flipY: true`。WebGL texImage2D 呼出時に `gl.pixelStorei(gl.UNPACK_FLIP_Y_WEBGL, true)` が作動し、texture row 0 = bitmap bottom になる。WebGL の UV convention (bottom-left origin、top of screen UV.y=1)と整合して正立表示。

WebGPU `copyExternalImageToTexture` は texImage2D 的な pixelStorei 自動処理を持たず、`flipY` を引数で明示する必要がある。

### Fix (MediaTexture.ts)

```typescript
// packages/film-lab-renderer/src/webgpu/MediaTexture.ts

static fromImageBitmap(device, bitmap, opts = {}): GPUTexture {
  ...
  device.queue.copyExternalImageToTexture(
    { source: bitmap, flipY: true },  // ← false → true
    { texture },
    { width: bitmap.width, height: bitmap.height },
  );
  return texture;
}

static fromVideoElement(device, video, target, opts = {}): GPUTexture {
  ...
  device.queue.copyExternalImageToTexture(
    { source: video, flipY: true },  // ← false → true
    { texture },
    { width, height },
  );
  ...
}
```

JSDoc に Y orientation 解説追記。

### 吸収先

本 chat で先行実装したが、並列 codex agent の `3e205386 Implement WebGPU preview stabilization and export convergence` が MediaTexture.ts を +25 行改変(stabilization 関連)する際に flipY:true も含めて取り込んだため、`f67e0702` 時点の working tree diff には現れない。現行 HEAD での挙動は正しく flipY:true。

### 旧コード (`FilmLabWebglPanelBackdrop.tsx` drawImage 方式)

### 失敗モード

```typescript
// packages/film-lab-ui/src/FilmLabWebglPanelBackdrop.tsx (全面書き換え)

type CanvasWithCaptureStream = HTMLCanvasElement & {
  captureStream?: (frameRate?: number) => MediaStream;
};

export function FilmLabWebglPanelBackdrop({ filmLabCanvasRef, enabled }) {
  const videoRef = useRef<HTMLVideoElement>(null);
  const streamRef = useRef<MediaStream | null>(null);

  useEffect(() => {
    if (!enabled) return;
    let cancelled = false;
    let attachRafId = 0;

    const attach = () => {
      if (cancelled) return;
      const video = videoRef.current;
      const src = filmLabCanvasRef.current?.getWebGlCanvas?.() as CanvasWithCaptureStream | null;
      if (!video || !src) {
        attachRafId = window.requestAnimationFrame(attach);
        return;
      }
      if (typeof src.captureStream !== "function") {
        console.warn("[FilmLabWebglPanelBackdrop] captureStream unavailable");
        return;
      }
      if (src.width < 2 || src.height < 2) {
        attachRafId = window.requestAnimationFrame(attach);
        return;
      }
      try {
        const stream = src.captureStream(30);
        streamRef.current = stream;
        video.srcObject = stream;
        void video.play().catch(() => { /* autoplay policy */ });
      } catch (err) {
        console.warn("[FilmLabWebglPanelBackdrop] captureStream failed", err);
      }
    };
    attachRafId = window.requestAnimationFrame(attach);

    return () => {
      cancelled = true;
      if (attachRafId) window.cancelAnimationFrame(attachRafId);
      const video = videoRef.current;
      if (video) {
        video.pause();
        video.srcObject = null;
      }
      const stream = streamRef.current;
      if (stream) for (const track of stream.getTracks()) track.stop();
      streamRef.current = null;
    };
  }, [enabled, filmLabCanvasRef]);

  if (!enabled) return null;

  return (
    <video
      ref={videoRef}
      muted autoPlay playsInline
      className="film-lab-webgl-backdrop-canvas pointer-events-none absolute inset-0 z-0 h-full w-full rounded-[inherit]"
      style={{
        objectFit: "cover",
        objectPosition: "100% center",
        filter: "blur(20px) saturate(1.18) brightness(0.88)",
        transform: "scale(1.12)",
      }}
      aria-hidden
    />
  );
}
```

### Why it works

- `canvas.captureStream(30)` は HTMLCanvasElement 標準 API、WebGPU context でも動作(Chromium 112+)
- 30fps で canvas pixel が MediaStream に流れる
- `<video>` 要素は DOM 上の通常のメディア要素で、独立した合成レイヤーだが backdrop-filter / filter が通常通り作動
- CSS `filter: blur(20px)` は video 要素の pixel に対して GPU blur を実行 → **glass morphism 視覚効果確定**

### 位置合わせの tradeoff

完全な pixel alignment は `object-position` を毎フレーム計算すれば可能だが、視覚的に 20px blur された状態では panel の右寄りに canvas の右側を見せるだけで十分自然。`object-fit: cover` + `object-position: 100% center` で固定。

## 11. Chromium Compositor Theory (WebGPU canvas の制約)

### 観測事実

- WebGPU canvas 上に CSS `backdrop-filter` を付けた兄弟 / 親要素 → **blur 効果視認できず**(outer / `::before` 両方試行)
- 2D canvas context の `ctx.drawImage(webgpuCanvas, sx, sy, sw, sh, ...)` → **silent failure**(例外なし、透明のまま)
- `<video>` + `canvas.captureStream()` → **成功**(blur 効く)

### 根底メカニズム

Chromium は GPU accelerated content(WebGL / WebGPU canvas、特定の `<video>`、`transform: translate3d()` 要素など)を「別 compositor layer」として管理する。

CSS `backdrop-filter` の仕様上:
- 要素の backdrop = 自分の下に visibility 可能性のある祖先と兄弟の合成結果
- しかし実装側で各 layer は独立した GPU texture で管理されるため、`backdrop-filter` を applied する layer の texture だけで blur 計算する
- 別の accelerated layer(WebGPU canvas)の pixel は別 texture で隔離されており、backdrop-filter の「背後」に含まれない

`ctx.drawImage(webgpuCanvas)` も同様:
- 2D context は CPU readback が必要
- WebGPU accelerated canvas の swapchain texture は GPU resident、CPU sync readback は expensive
- Chromium は最適化として WebGPU canvas → 2D context drawImage を deny ないし empty return する(実装依存)

### なぜ `<video>` + captureStream は効くのか

- `captureStream()` は canvas → MediaStream エンコード経路で、browser 内部で独立した capture frame queue を回す
- `<video>` 要素は MediaStream consumer として合成される、**通常の DOM 合成レイヤーに属する**
- CSS `filter`(要素自身の pixel にかかる filter)は `<video>` の出力 pixel に対して GPU で実行 → ✅

### WebGL canvas で問題が起きなかった理由

旧 WebGL backend 時代の THREE.WebGLRenderer は `preserveDrawingBuffer: true` で canvas を作っていた。これにより:
- WebGL canvas も accelerated layer だが、swapchain texture は保持され CPU readback 可能
- `ctx.drawImage(webglCanvas)` は drawing buffer の preserved state を読むため成功
- CSS `backdrop-filter` の compositor 経由でも読める実装挙動差があった

WebGPU には `preserveDrawingBuffer` 相当の API が存在せず、swapchain は present 後に invalidate される。そのため同じ手法が機能しない。

### 実用的 implication

本プロジェクトの教訓: **WebGPU 上で glass morphism を実現するなら captureStream + video が現時点の唯一の robust path**。backdrop-filter / drawImage に依存する設計は WebGPU に移行する際に必ず見直す必要がある。
