### 1-2. 起動後の DevTools Console エラー(新 chat で修正)

```
[Viewport] WebGPU backend bootstrap failed — falling back to WebGL
TypeError: Failed to execute 'configure' on 'GPUCanvasContext':
  Unsupported canvas context format 'rgba8unorm-srgb'.
    at e.create (WebGPUBackend-K3LM33LH-CPb-WWr0.js:1:848)

THREE.WebGLRenderer: A WebGL context could not be created.
  Reason: Canvas has an existing context of a different type

Uncaught (in promise) TypeError: e is not a function
  at new mf (index-Bg8YtZso.js:3957:32151)
```

**連鎖構造**:
1. `GpuContext.create()` が `context.configure({ format: "rgba8unorm-srgb", ... })` を呼ぶ(← WebGPU spec 違反)
2. `configure()` が throw → Viewport.create の catch → `prefer: 'webgl'` fallback へ降格
3. しかし `canvas.getContext("webgpu")` が既に呼ばれていて canvas が webgpu context 型に束縛済
4. `new THREE.WebGLRenderer({ canvas })` が「existing context of a different type」で失敗
5. 両 backend 失敗 → renderer undefined → 下流の `new mf(...)` で `e is not a function`

---

## 2. 根本原因

**WebGPU spec**: `GPUCanvasContext.configure()` の `format` は **`bgra8unorm` / `rgba8unorm` / `rgba16float`** のみ許可。`-srgb` variant は禁止。sRGB view が必要な場合は `viewFormats: ["rgba8unorm-srgb"]` を渡し、`getCurrentTexture().createView({ format: "rgba8unorm-srgb" })` で取り出す。

関連ファイル:

| path | 行 | 現状 |
|---|---|---|
| `packages/film-lab-renderer/src/webgpu/GpuContext.ts` | 28 | `readonly canvasFormat: GPUTextureFormat = "rgba8unorm-srgb";` |
| `packages/film-lab-renderer/src/webgpu/GpuContext.ts` | 73-80 | `context.configure({ format: "rgba8unorm-srgb", ... })` ← 違反 |
| `packages/film-lab-renderer/src/webgpu/GpuContext.ts` | 101 | `getCurrentTexture().createView()` ← default format、view 指定なし |

render pipeline 側で `colorAttachments[].format: "rgba8unorm-srgb"` を期待している箇所は:

- `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:135`(blit pass)
- `packages/film-lab-renderer/src/webgpu/shaders/blit.frag.wgsl.ts`、`composite.frag.wgsl.ts`、`filmlab.frag.wgsl.ts`(shader コメント上)

## 3. 方針(user 決定、2026-04-18)

### 3-1. Fallback は作らない

- WebGPU bootstrap 失敗時の WebGL fallback は **排除**
- 理由: silent degradation、code path 倍増、bootstrap-済-canvas 汚染のような「前提崩し」バグの温床
- user 明示 feedback: 「フォールバックはバグの温床になるので行いません」
- life repo に feedback memory 保存済: `feedback_no_fallback_bug_hotbed.md`
- **DIRECTION §1 D1(Three.js 切る、Pure WebGPU)と一貫**

### 3-2. WebGPU 不可環境は非対応

- 起動時 `isWebGPUSupported()` false or `GpuContext.create()` throw → **explicit エラー表示で起動中止**(白画面ではなく、user に対応不可環境であることを明示)
- 対象環境の最低線(想定):
  - macOS 14+ Safari / Chrome / Electron(本アプリ Electron 37 系)
  - Apple Silicon Metal 3 対応 GPU
- Intel Mac / 旧 macOS は ship 対象外(SHIP-READINESS で明示)

## 4. 新規 chat で実装するスコープ

### 4-1. 必須修正

**A. `GpuContext.ts` の canvas config を spec 準拠に**

```typescript
// 現状(line 27-28)
readonly canvasFormat: GPUTextureFormat = "rgba8unorm-srgb";

// 修正案
readonly canvasConfigFormat: GPUTextureFormat = "rgba8unorm";    // configure 用
readonly canvasFormat: GPUTextureFormat = "rgba8unorm-srgb";     // view / pipeline 用、変更なし

// 現状(line 73-80)
context.configure({
  device,
  format: "rgba8unorm-srgb",
  ...
});

// 修正案
context.configure({
  device,
  format: "rgba8unorm",                    // ← 変更
  viewFormats: ["rgba8unorm-srgb"],        // ← 追加
  alphaMode: "opaque",
  colorSpace: "srgb",
  usage: GPUTextureUsage.RENDER_ATTACHMENT | GPUTextureUsage.COPY_SRC,
});

// 現状(line 100-102)
getCurrentTextureView(): GPUTextureView {
  return this.context.getCurrentTexture().createView();
}

// 修正案
getCurrentTextureView(): GPUTextureView {
  return this.context.getCurrentTexture().createView({ format: "rgba8unorm-srgb" });
}
```

これで:
- swapchain texture の実 format は `rgba8unorm`
- sRGB view を createView で作り、hardware OETF(rgba8unorm-srgb への書込 = sRGB encode)が効く
- render pipeline の `colorAttachments[].format: "rgba8unorm-srgb"` は従来通り
- shader 側の挙動は変わらない(書込 view が sRGB なので hw encode は同じ)

**B. Fallback 排除**

- `packages/film-lab-renderer/src/Viewport.ts` の WebGPU→WebGL fallback 経路を削除
- `packages/film-lab-ui/src/FilmLabCanvas.tsx` の `prefer: effectivePref` 分岐を `prefer: 'webgpu'` 固定(desktop build)に
- WebGPU 不可環境用の **explicit error UI** を追加(例: `<WebGPUUnsupportedNotice />`)
- `apps/web` / batch-pipeline / video-export-pipeline は `prefer: 'webgl'` 固定のまま(v1.0 scope、別 consumer)

### 4-2. 検証項目

1. `bunx tsc --noEmit`(packages/film-lab-renderer / film-lab-ui / apps/desktop-film-lab-batch)
2. `bun run test`(vitest 52 件、WebGPU 側 pipeline compile-validate 含む)
3. `bun run build`(apps/desktop-film-lab-batch、WebGPU split chunk が生成されるか)
4. `bun run dist:mac:unsigned` で DMG 再生成
5. macOS 26 実機で `codesign --force --deep --sign - /Applications/Filmtone.app` 後に起動
6. DevTools Console で:
   - `[Viewport] WebGPU backend bootstrap failed` が **出ないこと**
   - `[GpuContext] adapter: apple / metal-3` 的なログが出ること(Phase 0 Case A)
7. `v1.0-qa-runbook.md` Step 1-7 を実行

### 4-3. drop scope(本 chat 起因の議論を持ち越さない)

- Fallback の改善案(fresh canvas 生成 etc.)は **全て却下**、一切実装しない
- WebGPU path が動かない環境の「動きだけでも確保」の議論は不要
- 既存の Viewport fallback コードがもし残っていても削る対象
