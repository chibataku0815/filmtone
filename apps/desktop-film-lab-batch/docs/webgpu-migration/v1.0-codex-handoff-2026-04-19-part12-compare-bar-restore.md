## 1. 60-second summary

- **What landed**: a v1 (toggle-only, no draggable split) compare bar on
  WebGPU. When toggled ON, the present pass is replaced by a full-screen
  "ungraded source" pipeline that samples raw `mediaTexture` with the
  same cover/contain fit math the filmlab + composite passes use. Slot
  params (`paramsA` / `paramsB`) are intentionally **ignored** on
  WebGPU v1 — the WebGL dual-slot simultaneous A/B render parity stays
  deferred to a follow-up phase.
- **Why this scope**: user explicitly chose minimum-GPU-effort over full
  WebGL parity. Restoring the visible "before vs after" toggle is the
  goal; dual-slot grading adds expense and architectural surface that
  was deemed not worth it for v1.
- **Approach**: 1 new WGSL shader + 1 new pipeline + 1 new bind group +
  1 new uniform buffer + `setComparePair` method on `WebGPUBackend` +
  capability flag flip on `GpuContext` + `Viewport.setComparePair`
  delegate routes to webgpu when active. No UI / control panel
  refactors needed — `previewSupportsCompare` (FilmLabCanvas.tsx:1159
  AND condition) starts returning true automatically once both flags
  flip.
- **Diff stat**: 175 insertions, 11 deletions across 5 modified files +
  1 new file. ~120 LOC of net implementation, ~55 LOC of comments and
  defensive structure.
- **Headless gates** (run after implementation, all green): tsc
  (film-lab-renderer) ✓, build:renderer (tsup) ✓, build:renderer

## 4. Behavioral spec (what the user will see)

| Surface | Behavior |
|---|---|
| **Space key (hold)** | Press-and-hold → ungraded source replaces the canvas. Release → grade restored. Snappy, no flicker. |
| **V key** | Toggle compare mode on/off. Same visual as Space hold but latched. |
| **A/B Compare button (control panel)** | Same as V key. |
| **Tab key (in compare mode)** | Switch active slot. Right side ("after") updates to reflect the now-active slot's grade. Left side stays as ungraded source. |
| **Before/After button (control panel)** | Click toggles. Same visual as Space. |
| **Canvas cursor** | `col-resize` while `previewSupportsCompare` is true (i.e., always now on WebGPU). The drag-handler is wired but does nothing visible because the WGSL doesn't actually split — the toggle is full-screen. |
| **Compare HUD chip** | Renders as before (computed in UI regardless of backend). The "drag to split" hint is now a slight UX lie on WebGPU (no draggable bar) — accepted v1 cost; can be conditionally hidden in a UI follow-up. |
| **Motion blur + compare** | When compare toggles on, motion blur is implicitly skipped for that frame's present (compare priority). When compare toggles off, motion blur resumes. No banding / pop because the ring buffer keeps writing as usual. |
| **Readback (export / golden tests)** | Compare path also writes to `readbackView` so export captures the ungraded source correctly when compare is active. |

## 5. Explicit deferrals (post-v1 work)

- **Dual-slot simultaneous A/B render** (WebGL parity): would require
  running the grade pipeline twice per frame with different params.
  Not in scope. Code paths to add: a second grade pipeline invocation
  with `compareParamsB` swapped in, then a split-blend shader that
  composites slotA and slotB side-by-side. Scope it as a separate
  feature work item.
- **Draggable split bar UI**: the cursor / HUD / pointer-drag handlers
  are still wired (they get enabled by `previewSupportsCompare`), but
  the WebGPU compare shader is full-screen toggle only. The drag does
  nothing visible. To restore, add a `splitPosition` uniform path to
  the compare shader and use the existing `setSplitPosition` (already
  routed to WebGPU at `WebGPUBackend.ts:1224`).
- **"Drag to split" HUD copy** (`compare.dragHint` i18n key): is now a
  slight lie on WebGPU. Either change the WebGPU code to honor the
  drag bar (the previous bullet), or conditionally hide the hint when
  `backendKind === 'webgpu'` in the UI.

## 10. User-side verification checklist (manual desktop QA)

Run all of these in one session. The first 3 are about this chat's
work; the last is the bundled outstanding 10-min smoke test from
part-7 §3.3.

### V1 — Compare bar (this chat's deliverable, ~5 min)

1. `cd apps/desktop-film-lab-batch && bun run desktop` (or the existing
   dev workflow).
2. Open any image; let the preview render once.
3. Press and hold **Space** — verify the canvas immediately shows the
   ungraded source, release shows the graded result.
4. Press **V** — verify same visual, latched.
5. With compare ON, press **Tab** — verify the *right side* (after)
   updates to reflect the new active slot. The left side (before)
   should stay as ungraded source. (The "right side" caveat: because
   v1 is full-screen toggle, "right side" is a visual approximation —
   the whole canvas just shows the new slot's grade when compare is
   off and ungraded source when on. There is no actual split.)
6. Press **V** again to release compare. Verify normal grade returns.
7. Click the **Before/After** button in the control panel — verify
   toggle behavior.
8. Click the **A/B Compare** button — verify toggle behavior.

**Pass criteria**: bar (cursor + HUD chip) appears, toggle is snappy,
no flicker, no console errors.

### V2 — No-regression (compare OFF, ~2 min)

9. Toggle compare OFF. Drag a few grade sliders. Verify everything
   renders normally (no visual artifacts, no extra latency vs prior
   build).
10. Open a video file. Verify playback works with compare OFF (video
    texture path, separate from image path).

### V3 — Hard-mode + Light Shafts smoke (outstanding from part-7 §3.3,
bundled here, ~10 min)

11. Apply a Hard-mode preset (cross-filter strength > 0). Verify
    cross-filter spikes render correctly with no stuck temporal echoes
    (this is the headline behavior `8774de55` shipped, and the
    temporal-decay refinement of `7ebdd1ba` + `dcea8518` polished).
12. Apply Light Shafts (`shaftIntensity > 0`) on top. Verify shafts
    render around bright highlights and blend additively with the
    composite.
13. With both active, scrub time forward / backward. Verify no flicker,
    no orientation drift, no off-by-one in the post-chain.
14. Toggle compare on top of all this. Verify ungraded source (no
    cross-filter, no shafts) appears correctly. Toggle off — full
    chain restored.

### V4 — Devtools console

15. Open devtools Console. Confirm zero `[GpuContext]` /
    `[FilmLabCanvas] Viewport.create failed` /
    `canvas.webgpuInitFailed` messages. Pipeline-validation errors
    typically print at backend init; they should be silent.
