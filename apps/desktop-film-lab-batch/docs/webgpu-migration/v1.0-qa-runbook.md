# v1.0 QA Runbook — 10〜15 分の実機動作確認

**対象**: `release/filmtone-1.0.0-arm64.dmg`(194 MB、ad-hoc codesign、SHA-256 `8cfd1734…f6501a8`)
**ハードウェア前提**: macOS 11+ arm64(M1 以降)、外部ディスプレイなしで OK
**判断**: 全 Step 通過 → ship。単一 Step で blocker 級の所見があれば → hold + issue 起票

---

## ⚠️ 最重要の検証点: プレビューと書き出しの色が一致するか

v1.0 では **プレビューだけ WebGPU**(rgba16float、no-clamp)、**ビデオ書き出しは引き続き WebGL2**(rgba8、clamp)。
パイプライン順序と LUT は同一なので通常は同じ見えになるが、**highlight が 1.0 を超えるシーン**では理論上ズレうる。
v1.0 ship の生死はここ → Step 3 / Step 5 が **プレビュー vs 書き出しフレームの色マッチ** を目視で突き合わせる設計になっている。

## Pre-flight(2 分)

1. `open /Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/apps/desktop-film-lab-batch/release/filmtone-1.0.0-arm64.dmg` で DMG マウント
2. `Filmtone.app` を `/Applications` にドラッグ(上書き OK)
3. 右クリック → 「開く」で初回起動(ad-hoc 署名なので Gatekeeper 警告が出たら許可)
4. **アプリが起動したら DevTools を開く**(`Cmd + Option + I`)→ Console タブ
   - Expected: `[GpuContext]` で始まるログに `apple` / `metal-3` が含まれる
   - もしくは `[Viewport] WebGPU backend bootstrap failed — falling back to WebGL` が出たら **即 hold**(Case C、direction chat へ escalate)
5. Activity Monitor で `Filmtone Helper (GPU)` が存在することを確認(任意)

## Step 1: 起動 + ベースライン静止画(1 分)

1. Film Lab タブに自動遷移しているはず
2. 左上の 📂 ボタン → 手元の **highlight-rich な静止画**(夕焼け / 逆光 / 白いドレス等)を 1 枚選ぶ
   - 手持ちがなければ `chibatakumi-portfolio/apps/desktop-film-lab-batch/test/golden/source-images/01-highlight-sunset.png` が合成 highlight ファイル
3. **Expected**:
   - 画像が 1 秒以内に表示される
   - Console に WebGPU 関連のエラーなし
   - Console に THREE 関連のエラーなし(WebGL context 競合の兆候なし)
4. プリセット `cinematic` / `portra` / `bw` を順にクリック
   - **Expected**: クリック直後に色が変わる。フリーズなし

**Pass 条件**: 画像が出る・プリセット切替が即時反映・console error 0

---

## Step 2: 動画プレビューの基礎動作(3 分)【最重要】

1. 📂 ボタン → **動画ファイル**を 1 本選ぶ
   - 推奨: `.mov`(H.264)か `.mp4`。**ProRes はやめる**(Chromium 非対応なので Progressive loading 経路に入り本筋がブレる)
   - 手元になければ FX3 / S1II の 10〜30 秒クリップで OK
2. 画面下部のトランスポート UI で再生 ▶️
3. **Expected(critical)**:
   - 動画が再生される。**最初のフレームで固まらない**
   - 再生中のフレームレートが視覚的に 30 fps 前後(カクつき・ストップ&ゴーなし)
   - シーク(progress bar ドラッグ)が機能する
   - 再生速度 1x / 2x / 3x トグルが効く
4. **再生中のまま**プリセット `cinematic` → `portra` → `bw` を切替
   - **Expected**: 切替直後のフレームで色が変わる。フレームが飛ばない・止まらない
5. 再生 → 一時停止 → 再生 → シーク の往復を 5-6 回
   - **Expected**: 毎回同じ位置から同じ色で再開する

**Pass 条件**: 動画が滑らかに再生・プリセット切替で色が追従・シーク無破綻

**Fail 時の典型症状**:
- 「最初のフレームで止まり以降更新されない」→ `Viewport.setTexture` → `createImageBitmap(video)` の generation counter が stale と判断している疑い。FilmLabCanvas.tsx の `queueSetTextureWebGPU` を調べる
- 「再生中に黒フレームが混じる」→ bitmap upload の race。同じく `queueSetTextureWebGPU` の `generation` ガードを疑う
- 「preset 切替で色が変わらない」→ `setParams` が WebGPU backend に届いていない。`Viewport.setParams` の分岐を確認

---

## Step 3: 動画書き出し — preview と export の色が一致するか【v1.0 最大のリスク】

1. Step 2 で読み込んだ動画を **highlight が入るフレーム**にシーク(夕日 / 窓 / 白いドレス等が画面内にある地点)
2. プリセット `cinematic` を選ぶ(highlight がよく動くので差が出やすい)
3. プレビューでそのフレームを **「画面キャプチャ」**(Cmd+Shift+4、または 📥 Save PNG で現在フレームを出力)→ ファイル A として保存
4. 同じプリセット・同じ動画のまま「動画を書き出す」(Export video)を実行
   - 画質は既定(H.264 1080p 等)で OK
   - 10 秒以内のクリップ推奨(短くて OK、色確認だけなら 3 秒でも可)
5. 書き出した MP4 を **QuickTime Player で開いて同じフレームにシーク** → そのフレームをスクリーンショット → ファイル B として保存
6. **A と B を並べて開く**(macOS Preview で 2 up 表示、または `open A.png B.png`)
7. **Expected**:
   - 全体のトーン(露出・コントラスト)が同じ
   - ハイライト部の色が同じ(夕日のコア / 窓の白飛び具合)
   - シャドウの締まり方が同じ
   - 色味(temperature / tint)が同じ
8. **許容差**:
   - 圧縮ノイズ由来の微細なテクスチャ差 → OK
   - 全体のトーンや色が**知覚できるレベルで違う** → blocker

**Pass 条件**: 知覚レベルで色が一致(A ≒ B)

**Fail 時の判定フロー**:
```
A と B が違う
  ├─ highlight だけが違う(B が WebGL 由来でクリップしている)
  │    → 想定内のリスク顕在化。v1.1 で export を WebGPU にする方向で ship 判断
  │      するか、v1.0 で preview も clamp する短期 patch を入れるか選ぶ
  ├─ 全体のトーンが違う
  │    → 想定外。soft-shaper / LUT2 のパスが preview と export でズレている疑い
  │      → hold、調査
  └─ どちらでも判断が難しい
       → hold、別ハンドオフで詳細調査
```

**この step が v1.0 ship の生死を分ける**。QA の中で最も丁寧にやる。

---

## Step 4: LUT(.cube)の読み込み(2 分)

1. 手元に `.cube` LUT があれば(なければ skip で OK):
2. LUT ファイルを Film Lab ウィンドウにドラッグ&ドロップ
3. **Expected**:
   - LUT 適用後の色が v0.6.x と目視で同等(highlight が極端にクリップしたり、シャドウがポスタライズしたりしない)
   - プリセットに LUT を重ねた場合の挙動が直感的

**Pass 条件**: LUT 適用結果が「色が正常に載っている」と感じられる

---

## Step 5: 再度の動画書き出し + ストレス(3 分)

1. Step 2 の動画に **別のプリセット**(Step 3 と違うやつ、例: `portra`)を適用
2. もう 1 本書き出し
3. 書き出し中 / 書き出し後に preview を触る(プリセット切替、シーク)
   - **Expected**: 書き出しが完走する、preview が freeze しない
4. 書き出した動画を QuickTime で再生 → 一通り色が正常
5. **ウィンドウリサイズを 3-4 回**(画面の左右端をドラッグ)
   - **Expected**: リサイズ中に黒画面が混じらない、リサイズ完了後に preview が追従している
6. 別の画像 / 動画を 2-3 本続けて読み込む(drag&drop 連打)
   - **Expected**: リーク警告なし、最新の 1 本が正しく表示される

**Pass 条件**: 書き出し並列・リサイズ・連続読み込みで破綻なし

---

## Step 6: 終了時の片付け(1 分)

1. ウィンドウを閉じる
2. Console に以下が**出ていない**ことを確認(出ていたら note):
   - `[GpuContext] device lost: …`(unintentional lost)
   - THREE が吐く resource leak warning
   - WebGPU の validation error(`validation error: …`)
3. アプリを終了(Cmd+Q)
4. Activity Monitor で `Filmtone` 関連プロセスが残っていないことを確認

**Pass 条件**: クリーンに終了、リークなし
