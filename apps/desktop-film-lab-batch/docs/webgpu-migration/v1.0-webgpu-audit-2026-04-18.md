# Filmtone WebGPU Migration Audit (2026-04-18)

**Branch**: `feature/webgpu-migration-v1`
**Scope**: desktop preview path, shared renderer/UI surface, batch export, video export
**Purpose**: Phase 3 / ship-handoff docs のあとに、実装と API surface を改めて精査し、
「WebGPU 適応として何が完了していて、何が未完か」を明文化する。

> This document is a post-handoff audit. Read it together with
> [`SHIP-READINESS.md`](./SHIP-READINESS.md).
> `SHIP-READINESS.md` は phase chat 時点の gate evidence を残す文書であり、
> この audit はその後の詳細レビューで見つかった不足をまとめる。

---

## Executive Summary

- `feature/webgpu-migration-v1` は **desktop preview の WebGPU 化**としては大きく前進している。
- ただし、**Filmtone 全体の WebGPU migration が完了した状態ではない**。
- 重要な未解決点は次の 5 つ:
  1. WebGPU 動画 preview が live frame upload になっていない
  2. split / before-after / A-B compare が WebGPU で実質未実装
  3. WebGPU device loss / fatal render failure が preview recovery に伝播しない
  4. batch export がまだ WebGL 固定
  5. video export がまだ WebGL 固定
- このため、本 branch の正確な表現は
  **"WebGPU preview migration with known parity gaps"**
  であり、**"full WebGPU migration"** ではない。

---

## P1 Findings

### 1. WebGPU `setTexture()` は動画ソースを 1 回だけ snapshot している

**Summary**

WebGPU path の `Viewport.setTexture()` は `THREE.Texture` の source を
`ImageBitmap` に変換して 1 回だけ upload する。静止画では正しいが、
`THREE.VideoTexture` ではその後の frame 更新が GPU に届かない。

**Evidence**

- [`packages/film-lab-renderer/src/MediaLoader.ts`](../../../../packages/film-lab-renderer/src/MediaLoader.ts#L344-L360)
  は動画ロード時に `THREE.VideoTexture(video)` を返す。
- [`packages/film-lab-renderer/src/Viewport.ts`](../../../../packages/film-lab-renderer/src/Viewport.ts#L339-L362)
  は WebGPU path で `createImageBitmap(source)` → `setMediaFromBitmap(bitmap)` を実行する。
- [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L466-L488)
  は texture 差し替え時に `viewport.setTexture(result.texture)` を 1 回呼ぶだけ。
- その後の preview loop は
  [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L917-L935)
  で `viewport.render()` を回すだけで、動画 frame 再 upload を行わない。
- なお、
  [`packages/film-lab-renderer/src/webgpu/MediaTexture.ts`](../../../../packages/film-lab-renderer/src/webgpu/MediaTexture.ts#L45-L77)
  には `fromVideoElement()` が存在するが、現行 flow では未使用。

**Impact**

- desktop の既定 WebGPU preview で、動画再生・seek が初回 frame のまま止まる可能性が高い。
- これは v1.0 runbook が重視している「動画 preview 健全性」と正面衝突する。

**Recommendation**

- `Viewport` / `WebGPUBackend` に live video upload path を追加する。
- 最小案は `HTMLVideoElement` を保持し、`render()` 前または
  `requestVideoFrameCallback` で `copyExternalImageToTexture` を走らせること。

### 2. compare mode はまだ WebGL 専用 delegate

**Summary**

shared UI は compare mode を引き続き有効にしているが、WebGPU backend 側では
`setComparePair()` が no-op で、split 位置も shader に反映されていない。

**Evidence**

- [`packages/film-lab-renderer/src/Viewport.ts`](../../../../packages/film-lab-renderer/src/Viewport.ts#L294-L299)
  の `setComparePair()` は `this.webglBackend?.setComparePair(...)` のみ。
- [`packages/film-lab-ui/src/FilmLabControlPanelCore.tsx`](../../../../packages/film-lab-ui/src/FilmLabControlPanelCore.tsx#L442-L470)
  は compare UI から `viewport.setComparePair(...)` を継続的に呼ぶ。
- [`packages/film-lab-renderer/src/webgpu/gradeUniforms.ts`](../../../../packages/film-lab-renderer/src/webgpu/gradeUniforms.ts#L102-L103)
  では `splitPosition` を uniform に詰める。
- しかし
  [`packages/film-lab-renderer/src/webgpu/shaders/filmlab.frag.wgsl.ts`](../../../../packages/film-lab-renderer/src/webgpu/shaders/filmlab.frag.wgsl.ts#L28-L29)
  と
  [`packages/film-lab-renderer/src/webgpu/shaders/composite.frag.wgsl.ts`](../../../../packages/film-lab-renderer/src/webgpu/shaders/composite.frag.wgsl.ts#L17-L18)
  にある split / A-B compare は実 render path に未接続。

**Impact**

- before/after と A/B compare は desktop WebGPU build 上で UI state だけ進み、
  描画結果が変わらない。
- これは user-visible な機能回帰。

**Recommendation**

- WebGPU 側に compare 実装を入れる。
- すぐに入れないなら、`Viewport` に capability を持たせて UI から機能を隠す。

### 3. WebGPU loss が preview recovery に届かない

**Summary**

WebGPU backend は `device.lost` を監視しているが、その状態が `Viewport` 経由で
UI / desktop recovery logic に伝わっていない。

**Evidence**

- [`packages/film-lab-renderer/src/webgpu/GpuContext.ts`](../../../../packages/film-lab-renderer/src/webgpu/GpuContext.ts#L54-L57)
  は `device.lost.then(...)` で warn を出すだけ。
- [`packages/film-lab-renderer/src/webgpu/GpuContext.ts`](../../../../packages/film-lab-renderer/src/webgpu/GpuContext.ts#L107-L109)
  には `isLost()` があるが、consumer に露出していない。
- [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L1290-L1296)
  の `getPreviewHealth()` は WebGL の `isContextLost()` しか見ていない。
- [`apps/desktop-film-lab-batch/src/renderer/App.tsx`](../../src/renderer/App.tsx#L1279-L1292)
  は `getPreviewHealth().contextLost` を使って export 後の preview recovery を判断する。
- さらに
  [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L830-L843)
  では `Viewport.create()` 失敗しか UI state に変換しておらず、
  `await vp.prewarm()` や RAF 内 `viewport.render()` の fatal path は拾っていない。

**Impact**

- WebGPU device loss が起きても desktop は preview dead を認識できない。
- export 後の「再読み込みすべき preview」判定も WebGPU では効かない。

**Recommendation**

- `Viewport` に `isContextLost()` / `onContextLost()` を追加し、WebGL / WebGPU の両 backend で統一する。
- `FilmLabCanvas` は `Viewport.create()` だけでなく `prewarm()` / `render()` の fatal 失敗も
  rebuildable state に落とす。

### 4. batch export はまだ WebGL2 前提

**Summary**

photo batch pipeline は依然として WebGL2 availability を hard prerequisite にしており、
viewport 生成も `prefer: "webgl"` 固定。

**Evidence**

- [`apps/desktop-film-lab-batch/src/renderer/batch-pipeline.ts`](../../src/renderer/batch-pipeline.ts#L294-L296)
  は `isWebGL2Supported()` false で throw する。
- 同ファイルの
  [`L331-L341`](../../src/renderer/batch-pipeline.ts#L331-L341)
  で `THREE.WebGLRenderer` を生成する。
- 同ファイルの
  [`L394-L399`](../../src/renderer/batch-pipeline.ts#L394-L399)
  で `Viewport.create(..., { prefer: "webgl" })` を呼ぶ。

**Impact**

- desktop preview が WebGPU でも、実出力経路は WebGL のまま。
- preview / export の backend 分裂が継続し、色・機能・保守の drift を生む。

**Recommendation**

- preview と export が共有できる backend-neutral offscreen render session を抽出する。
- v1.1 以降の `GpuRenderer` 化を backlog ではなく、migration completion の本体として扱うべき。

### 5. video export もまだ WebGL2 前提

**Summary**

video export pipeline も batch と同じく WebGL2 hard dependency のままで、
viewport 生成が `prefer: "webgl"` 固定になっている。

**Evidence**

- [`apps/desktop-film-lab-batch/src/renderer/video-export-pipeline.ts`](../../src/renderer/video-export-pipeline.ts#L810-L812)
  は WebGL2 が無いと即 fail を返す。
- 同ファイルの
  [`L1021-L1035`](../../src/renderer/video-export-pipeline.ts#L1021-L1035)
  では `THREE.WebGLRenderer` + `Viewport.create(..., { prefer: "webgl" })` を使う。

**Impact**

- preview は WebGPU、動画書き出しは WebGL という split-path が固定化している。
- `SHIP-READINESS.md` が最大リスクとして挙げる preview/export highlight mismatch は、
  まさにこの構造から生じる。

**Recommendation**

- WebGPU offscreen render + readback (`copyTextureToBuffer`) を export 側に導入する。
- `video-export-pipeline` と `batch-pipeline` は同じ抽象に揃える。

## Secondary Gaps

以下は P1 ではないが、現状の docs / release framing を補正するために明記しておく。

- **WebGPU で inert な effect / control が残っている**
  - 現行 WebGPU が確実に処理しているのは core grade、bloom、halation、grain、vignette、motion blur。
  - 未接続なのは `diffusion`, `lensSoftness`, `crossFilter*`, `dustAmount`,
    `scratchAmount`, `shaft*`。
  - [`packages/film-lab-renderer/src/webgpu/compositeUniforms.ts`](../../../../packages/film-lab-renderer/src/webgpu/compositeUniforms.ts#L40-L52)
    はその差分を端的に示している。
  - `diffusion` は built-in preset が非 0 を持つため、UI 専用 gap ではなく preset parity に影響する。
- **Histogram は WebGPU で実質未対応**
  - [`packages/film-lab-renderer/src/Viewport.ts`](../../../../packages/film-lab-renderer/src/Viewport.ts#L302-L305)
    は WebGPU で `getHistogramPixels()` を返さない。
  - desktop app は histogram をデフォルト表示しているため、
    WebGPU build では placeholder 的な表示になる。
- **`prewarm()` は現行 bootstrap では no-op**
  - [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L890-L899)
    で media restore より前に `await vp.prewarm()` を呼ぶ。
  - しかし
    [`packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts`](../../../../packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts#L1094-L1095)
    は `mediaTexture` が無いと `render()` を即 return する。
- **`Viewport.getSplitPosition()` は WebGPU live state を返していない**
  - getter は pending params を見るが、setter は `frameState.splitPosition` に書いている。
  - そのため
    [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L1001-L1002)
    の download capture restore が壊れる。
- **WebGPU preview はまだ WebGL-era 8K texture cap を引き継いでいる**
  - [`packages/film-lab-ui/src/FilmLabCanvas.tsx`](../../../../packages/film-lab-ui/src/FilmLabCanvas.tsx#L552-L553)
    は renderer 無しのとき `8192` fallback。
  - `MediaLoader` は本当にそのサイズまで縮小するので、
    adapter limit を見ているわけではない。
- **テスト coverage が migration の危険箇所を守れていない**
  - backend negotiation
  - WebGPU video preview
  - compare capability mismatch
  - `device.lost` / preview recovery
  - `prewarm()` / `render()` failure path

## Recommended Refactor Order

1. **`Viewport` capability / health contract を導入する**
   - `backendKind` だけでは不足。
   - `supportsCompare`, `supportsHistogram`, `supportsLiveVideoTexture`,
     `maxTextureDimension2D`, `isContextLost`, `onContextLost` を追加する。
2. **WebGPU の live video upload path を first-class にする**
   - これは preview の correctness に直結する。
3. **preview/export 共通の offscreen render session を抽出する**
   - WebGPU migration completion の本体。
4. **UI を capability-gated にする**
   - compare / histogram / inert controls を backend に応じて隠すか disabled 化する。
5. **未接続 WGSL / module compile を整理する**
   - dormant shader compile を lazy 化するか feature gate する。
6. **migration regression tests を追加する**
   - `FilmLabCanvas` を mock backend で押さえる。
   - desktop 側は preview/export backend split を 1 本の integration test で監視する。
