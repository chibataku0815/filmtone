## 2. What this session committed

### 2.1 `07a9ae2b` — explicit offscreen session + renderer-native readback

Promoted the uncommitted checkpoint from the 2026-04-19 handoff to a
clean commit:

- backend-neutral offscreen seam now has an explicit WebGPU session
  (`webgpu-offscreen-render-session.ts`) and a no-fallback factory
  (`create-offscreen-render-session.ts`, default `prefer: "webgpu"`).

- `WebGPUBackend` mirrors the final present pass into an
  `rgba8unorm-srgb` readback target, copies it with
  `copyTextureToBuffer`, strips 256-byte row padding, and returns

  preserved.
- Batch export and video export now request explicit WebGPU offscreen.
- New offscreen tests landed.

### 2.2 `ca5de309` — composite parity fix (glow / grain / lens)

All three 2026-04-19 manual-QA findings addressed in the WGSL composite
shader + uniform packer, no pipeline-layout change, no backend-native
Three.js changes:

1. **Bloom / halation upside down** — the procedural fullscreen triangle
   derives `uv.y = y*0.5+0.5`, so each render pass flips texture rows
   once. The base path reaches the swap chain after an EVEN number of
   flips (media upload + filmlab + composite + blit); bloom/halation go
   through ONE more pass (prefilter), so they land with an odd number
   of flips and therefore arrive mirrored along y. Minimal fix: the
   composite shader now samples `uBloom` and `uHalation` at
   `vec2f(uv.x, 1.0 - uv.y)`, re-aligning them with the base without
   touching the pyramid or the vertex shader.
2. **Grain quality** — the WGSL composite now ports the WebGL grain
   model 1:1: silver-halide `sin/fract` per-pixel hash, per-channel
   chroma/luma separation (`chromaR`, `chromaB`), `grainSize`-driven
   low-frequency clump density modulation, and 3 Hz temporal stepping.
   Legacy `uGrain` / `uGrainSampler` bindings are left declared with a
   zero-weight contribution so the pipeline bind-group layout is
   unchanged.
3. **Lens softness + aberration edge soften** — ported the WebGL 8-tap
   cross+diagonal blur, edge mask (`smoothstep(0.25, 1.0, edgeR)`),
   gamma-corrected lens drive (`pow(lensSoftness, 0.78)`), and blur
   radius cap (≤ 4.2 px). The composite uniform gained a 4th vec4
   `lens = (lensSoftness, aberrationEdgeSoften, _, _)`; packer sized
   off the shared constant so no backend plumbing changes.

## 4. What is NOT verified yet — manual QA required

Three items must be checked on a real WebGPU desktop build (the parity
fix is visual by definition; headless tests cannot detect it):

1. **Glow orientation** — run preview with bloom + halation turned up,
   compare orientation of the glow against the base image. Before this
   session, the glow was mirrored along y; after the fix, glow should
   sit on the same side as its source highlight.
2. **Grain** — run preview with `grainIntensity` ≥ 0.5, sweep
   `grainSize` from 0 to 1. Before this session, grain looked
   "smooth / tiled"; after the fix, grain should read as per-pixel
   silver halide, with low-frequency clumping at higher `grainSize`
   and subtle colour grain from the per-channel chroma seeds.
3. **Lens softness + chromatic aberration** — sweep `lensSoftness` and
   the aberration strength slider. Before this session, those sliders
   had almost no effect in WebGPU preview; after the fix, the periphery
   should soften progressively with higher slider values.

All three of these live in the same commit, so a single pass of QA
covers the entire parity fix set.

## 6. Current open risks

- The 2026-04-19 renderer-native readback duplicates the final present
  pass into an extra `rgba8unorm-srgb` texture while readback is
  enabled. This is correct by construction but has not been benchmarked
  on a real desktop driver yet. If real video export shows a
  throughput regression, tune: keep readback opt-in and only enable it
  during actual export.
- Video export still contains intra-backend fallback concepts (WebCodecs
  retry → HTMLVideoElement seek path; WebGL PBO → sync `readPixels`).
  These are NOT backend fallbacks so they do not violate the
  no-fallback rule, but they should be revisited once parity is
  confirmed by manual QA.
- Batch export still encodes through `canvas.toDataURL(...)` and is
  NOT yet readback-driven. This is acceptable as a checkpoint but is
  a clear next cleanup target.

## 7. Recommended next steps

In this order:

1. **Run manual QA** on a real WebGPU desktop build against the three
   checklist items in §4. Report results.
2. **If QA passes:** move on to batch `toDataURL` cleanup (drive batch
   export through `readbackRgba8()` + a real PNG / JPEG encoder) and
   then decide whether to remove the remaining intra-backend fallback
   concepts in video export.
3. **If QA fails on glow orientation specifically:** inspect whether
   the regression is batch-only, video-only, or preview-only — the fix
   in this session assumes the orientation delta is uniform across all
   three; an asymmetric failure would suggest a second flip site (e.g.
   the video-export `vflip` in ffmpeg, or `setExportFlipY` toggled
   differently between paths).
4. **If QA fails on grain or lens softness specifically:** the model is
   a line-by-line port from the WebGL shader; most likely failure mode
   is a missing uniform route rather than a shader bug. Check
   `packCompositeUniforms` sources (`grainSize`, `grainRadialMix`,
   `lensSoftness`, `aberrationEdgeSoften`) against what the grade panel
   pushes into params.
