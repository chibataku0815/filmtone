# Filmtoneの次の更新では、音声とディテールの出方を見直しています

Status: candidate draft. Do not publish until Desktop public `1.7` and iOS
public `1.9` are both confirmed by truth scripts.

Filmtone の次の更新では、Desktop と iOS の両方で、動画を書き出したあとの仕上がりを見直しています。

中心になる変更は 2 つです。

- 通常の動画書き出しで、元の素材に音声がある場合は、出力した MP4 にも音声を残す。
- `Texture softness` / `質感のやわらかさ` で、細かい輪郭やディテールの出方を少し調整できるようにする。

新しい見た目の画面を大きく足すというより、書き出したファイルをあとで見返したときに気になる部分を直す更新です。Filmtone は色を決めるためのアプリですが、最後に残るのは編集画面ではなく、保存した動画ファイルです。そこに音が残っているか、細かい輪郭が強く出すぎていないかを見直しました。

## 1. 通常の動画書き出しで音声を残す

Desktop と iOS の通常の動画書き出しで、元の素材に音声がある場合、その音声を出力側にも残すようにしています。iOS では、アプリ内で録画したクリップにもマイク音声を含める方向です。

今回大事にしたのは、処理の途中で「音声を書き込む準備をしたから大丈夫」と見なさないことです。書き出しが終わったあと、完成したファイルをもう一度確認して、音声トラックがあるかを見るようにしています。

プレビューで音が聞こえることと、書き出したファイルに音が残ることは別です。ユーザーが最後に使うのは完成したファイルなので、Filmtone 側でもそこを見るようにしました。

ハイライト書き出しは、いまの設計では音声なしのままです。今回はすべての書き出しで音が残る、という更新ではありません。まずは通常の動画書き出しで、音声付き素材を音声付きの完成ファイルとして扱うところを整えています。

## 2. Texture Softnessで細かい輪郭の強さを調整する

もうひとつの変更は、`Texture softness` です。iOS では「質感のやわらかさ」として見える予定の調整です。

これは、画面の中心も含めた細かい輪郭や、デジタルっぽい局所コントラストを少し弱めるための軸です。

`Lens softness` とは役割が違います。`Lens softness` は、レンズや周辺の柔らかさに近い調整です。`Texture softness` は、画面全体にある細かい輪郭や質感の出方を扱います。

くっきり撮れた動画は見やすい一方で、色を作ったあとに、細い輪郭だけが強く残ることがあります。たとえば髪、布、葉、細かい文字、夜のノイズのような部分です。全体の色はよくても、そこだけシャープに見えすぎることがあります。

ただし、普通の blur をかけたいわけではありません。文字や髪までぼやけると、ただ解像感が落ちたように見えます。やりたいのはピンぼけではなく、細かい輪郭の主張を少し弱めることです。

そのため Texture Softness は、単純なぼかしではなく、細かい detail layer を見て、強い輪郭はなるべく残しながら、細かいディテールの出すぎを抑える方向にしています。素材情報から輪郭が強く立ちやすそうだと分かる場合は、控えめな source detail bias も足します。

この補正は保存した Look には焼き込みません。素材ごとの補正を Look に入れてしまうと、その Look を別の素材に当てたときにも補正が付いてきてしまうからです。Look はできるだけ持ち運びやすくし、素材ごとの補正は runtime 側で扱う方針です。

## 3. iOSとDesktopで色の考え方を分けない

今回の更新は、内部構造の整理ともつながっています。

iOS では、撮影、編集、書き出し、Look、Optics、Source Profile まわりを feature ごとに分けています。Desktop でも、native macOS アプリとして、プレビュー、通常の動画書き出し、静止画書き出しで同じ考え方を使えるようにしています。

ただし、native に寄せることは、iOS と Desktop で色の考え方を別物にするという意味ではありません。

最初の Filmtone は、WebGPU / WebGL renderer と shared TypeScript の色ロジックから始まりました。iOS の React + Capacitor も、その renderer path を iPhone に持ち込むための選択でした。その後、撮影や Live Look、書き出しの品質を上げるために、AVFoundation と SwiftUI 側の制御が必要になりました。

今の方向は、Web と native の勝ち負けではありません。色の考え方は shared core に置き、撮影や書き出しのように runtime quality が効くところは native で持つ。Filmtone はその形に寄せています。

## 公開後に試してほしいところ

公開後に試すなら、まずはいつもの Preset や Look を選び、音声付き素材を通常の動画として書き出してみてください。次に、Advanced の Texture Softness / 質感のやわらかさを少しだけ上げて、細かい輪郭の見え方がどう変わるかを見てください。

効き方は素材によって変わります。すべての素材を自動でいい感じにする機能ではありません。輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として見てもらうのが近いです。

かなり細かい更新です。でも、動画は最後のファイルで判断されます。音が残っているか、輪郭が強く出すぎていないか。Filmtone では、そういう少し地味なところも見ていきます。

作っている側としては、こういう細部に少しうるさいくらいでちょうどいいのかもしれません。
