Filmtone は、iPhone と Mac で動画の色味を整えるためのアプリです。スマホやカメラで撮った動画を読み込んで、質感のある動画として書き出します。

次の更新では、Desktop と iOS の両方に、デジタル感の強い部分の見え方を整えるための調整 `Texture Softness` / `質感のやわらかさ` を入れています。あわせて、通常の動画書き出しで音声が出力されない不具合を直しました。

書き出したファイルをあとで見返したときに、デジタル感の強い部分が強く出すぎていないか、という部分を見直す調整です。音声まわりは、もともと残るはずだったところで残っていなかったので、直しました。

## 1. Texture Softness でデジタル感の強い部分の強さを調整する

今回の更新で新しく入れた調整が、`Texture Softness` です。iOS では `質感のやわらかさ` として見える予定の調整です。

これは、画面の中心も含めたデジタル感の強い部分や、センサーや圧縮で生まれやすい局所コントラスト ── つまり「くっきりしすぎる部分」── を、少しだけ弱めるための軸です。

似た名前の `Lens Softness` とは役割が違います。`Lens Softness` は、レンズの周辺やフォーカスの落ち方に近い柔らかさを足す調整です。`Texture Softness` は、画面全体にあるデジタル感の強い部分そのものの強さを扱います。

最近の iPhone やアクションカメラの素材は、撮影時にカメラ側 (センサーや内部の画像処理) が、細かい輪郭を強めに見せる処理 (sharpening) をかけたうえで動画ファイルを作っています。これは撮って出しの段階ですでに焼き込まれている性質で、Filmtone 側で色を整えても弱まりません。色全体のバランスが取れたあとに、たとえば髪、布、葉、細かい文字、夜のノイズが乗った部分など、もともと立っていた細い輪郭だけが目立って見える、ということが起きやすくなります。

ただし、普通の blur (ぼかし) をかけたいわけではありません。文字や髪までぼやけてしまうと、ただ解像感が落ちたように見えるだけです。やりたいのはピンぼけではなく、デジタル感の強い部分の主張だけを少し弱めることでした。

そのため `Texture Softness` は、画面全体を均等にぼかすのではなく、デジタル感の強い部分の成分 (detail layer) だけを取り出して、強い輪郭はなるべく残しながら、細部の出すぎを抑える方向にしています。素材情報から、輪郭が強く立ちやすそうだと分かる場合は、控えめな初期値 (source detail bias) も足します。

ただし、この素材ごとの控えめな初期値は、保存した Look には焼き込みません。素材ごとの補正を Look に入れてしまうと、その Look を別の素材に当てたときに、撮影時の補正まで一緒に持ち運ばれてしまうからです。Look はできるだけ持ち運びやすくし、素材ごとの補正は runtime (実行時) 側で扱う方針です。

効き方は素材によって変わります。`Texture Softness` は、すべての素材を自動で良くする機能ではなく、輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として見てもらうのが近いです。

## 2. 通常の動画書き出しで音声が出力されない不具合を直しました

Desktop / iOS の通常の動画書き出しで、元の素材に音声があっても、書き出した MP4 に音声が残らない場合がありました。今回はそこを直しています。iOS では、アプリ内で録画したクリップにもマイク音声を含めるようにしました。

内部では、書き出しが終わったあとに完成 MP4 をもう一度開いて、音声トラックが残っているかを確認するようにしています。書き出し中の状態だけでは「音声が無事に書けたか」が判定できないことがあったので、完成ファイル自体を直接見るようにしました。

ハイライト書き出しは、いまの設計では音声なしのままです。今回の修正は、通常の動画書き出しの範囲です。

## 3. 公開後に試してほしいところ

まずはいつもの Look (`Stone` のようなフィルム調の仕上がりや、`Urban Creative` のような街並み向けの仕上がり、自分で保存した Look) を選び、Advanced にある Texture Softness / 質感のやわらかさを少しだけ上げて、デジタル感の強い部分の見え方がどう変わるかを見てください。音声付きの素材を通常の動画として書き出した場合は、完成ファイルに音声がそのまま残ることもあわせて確認できます。

繰り返しになりますが、効き方は素材によって変わります。すべての素材を自動でいい感じにする機能ではなく、輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として捉えてもらえると、外れにくいです。

動画は最後に書き出したファイルで判断されます。音が残っているか、デジタル感の強い部分が強く出すぎていないか ── そういう、表に出にくいところを今回は見ています。

## 4. 作っている側で考えていること

今回の更新は、内部構造の整理ともつながっています。iOS では、撮影、編集、書き出し、Look、Optics (レンズ的な調整)、Source Profile (撮影素材ごとの初期値) まわりを、機能ごとに分けて整理しました。Desktop でも、macOS 純正のアプリとして、プレビュー、通常の動画書き出し、静止画書き出しで、同じ考え方を使えるようにしています。

各 OS 純正の仕組みに寄せていくことは、iOS と Desktop で色の考え方そのものを別物にする、という意味ではありません。いまの iOS と Mac の Filmtone は、どちらも Apple 純正の Swift で書かれた native アプリです。撮影や書き出しは AVFoundation、色のグレーディング処理は Core Image (Apple の GPU 画像処理の仕組み)、画面は SwiftUI と AppKit、という形です。

色そのものの決め方 (どの Look がどんな curve や LUT を持つか、どんな順序で処理を積むかなど) は、iOS と Mac で別物にせず、共通の TypeScript で書いた 1 つの core に置いています。そこから Swift コードを自動生成して、iOS と Mac の両方の native アプリが同じものを参照する作りです。色の決め方は共有して、撮影や書き出しのように「その場の処理の質」が直接出るところだけ、各 OS 純正の仕組みに任せる、という方針です。

なお、初期の Filmtone はブラウザ上の描画エンジン (WebGPU / WebGL) を iOS / Mac に持ち込む形で始まりました (iOS 版では React と Capacitor を経由)。いまもこの描画エンジンは残っていて、紹介ページなどの Web 側で使われていますが、iOS / Mac の shipping アプリの runtime はそこから native Swift に移っています。

作っている側としては、こういう細部に少しうるさいくらいで、ちょうどいいのかもしれません。
