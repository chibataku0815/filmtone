色は決まる。でも素材によっては、なぜかフィルム寄りに振りきらない瞬間があります。

髪の一本一本が立つ。布の繊維が見えすぎる。夜のシーンで、ノイズが粒として残る。── 撮影時にカメラ側で焼き込まれたシャープネスが、グレーディングをかけたあとに、改めて主張しはじめる現象です。

Filmtone は、iPhone と Mac で動画の色味を整えるアプリです。撮影した素材を読み込み、Look (フィルム調・街並み調・自作) を当てて、質感のある映像として書き出します。次の更新では、その「あとから残るデジタル感」を後段で抑えるための新しい調整軸 `Texture Softness` / `質感のやわらかさ` を、Desktop と iOS の両方に入れました。あわせて、音声付きの動画を normal export で書き出すと、撮ったときの音がそのまま完成 MP4 に残るようになります。

## 1. Texture Softness ── 焼き込まれたシャープネスを、後段で外す

iPhone でも、Action cam でも、GoPro でも ── センサーから動画ファイルに書き出される段階で、カメラ側はすでに細部を強調する画像処理 (sharpening) を済ませています。撮って出しで「気持ちよく見える」ようにチューニングされた処理ですが、ここに後からフィルム寄りのグレーディングを乗せると、本来なら自然に溶けてほしい細部だけが残り、輪郭が浮く。これがいわゆる「デジタル感」の正体のひとつです。

問題は、これがファイルに焼き付いていること。いくら curve や LUT を当てても、色のレイヤーとシャープネスのレイヤーは別物なので、グレーディング側からは弱められません。

`Texture Softness` ── iOS では `質感のやわらかさ` ── は、このディテール層だけを取り出して、強さを後段で扱うための軸です。

似た名前の `Lens Softness` とは役割が違います。`Lens Softness` は、レンズ周辺やフォーカスの落ち方に近い「ふんわり」を **足す** 方向。`Texture Softness` は逆に、すでに焼き込まれた「くっきり」の主張を **落とす** 方向です。

ここで大事なのは、画面全体を blur (ぼかし) するわけではない、ということ。文字や髪まで一律にぼやけると、ただ解像感を失った映像になります。やりたいのはピンぼけではなく、ディテール側の主張だけを下げて、強い輪郭は残すこと。そのために `Texture Softness` は、画面からディテール成分 (detail layer) だけを取り出し、その強さを独立に扱う実装になっています。

素材の特徴から、シャープネスが強く焼き込まれている撮影だと判定できる場合は、控えめな初期値 (source detail bias) も自動で足します。ただしこの素材依存の補正は、保存した Look には焼き付けません。素材ごとの癖を Look に混ぜてしまうと、その Look を別の素材に当てたときに、撮影時の補正まで一緒に引き連れてしまうからです。

Look は素材を超えて持ち運べるもの、素材ごとの補正は実行時 (runtime) に任せるもの ── ここを明確に分けています。

万能ではありません。すべての素材を自動で良くする機能ではなく、「輪郭が強く出すぎている素材に対して、後段で弱められる」という、選択肢を一段増やす更新です。

## 2. 撮ったときの音が、書き出した動画にそのまま入ります

通常の動画書き出しで、元素材に音声があるとき、その音声がそのまま完成 MP4 に残るようになります。iOS では、アプリ内で録画したクリップに、撮影時の mic 音声がそのまま含まれます。

内部では、書き出しが完了したあとに完成 MP4 を改めて開いて、音声トラックが残っているかを直接確認する形に変えました。書き出し中の状態だけでは「音声が正しく書けたか」を判定しきれないことがあったので、書き出し中ではなく、書き出した結果を見る、というシンプルな方針です。

ハイライト書き出しは、現状の設計のまま音声なしです。今回触ったのは通常の動画書き出しと iOS の録画クリップの範囲。

## 3. 公開後に試すなら、最初の 30 秒

普段使っている Look ── `Stone` (フィルム調)、`Urban Creative` (街並み向け)、あるいは自作の Look ── を選んだあと、Advanced の `Texture Softness` / `質感のやわらかさ` を少しだけ動かしてみてください。

特に効きが見えやすい素材:

- iPhone の夜景 (ノイズの粒が落ち着くか)
- 髪、布、葉などディテール密度の高い被写体
- iPhone Pro や action cam の log 素材

音声付き素材を通常書き出しにかければ、完成ファイルに音がそのまま残ることもあわせて確認できます。

動画は最後に書き出されたファイルで判断されます。音が残っているか、撮って出しの硬さが少し押し戻されているか ── 編集中には気付きにくく、書き出した後に効いてくる部分を、Filmtone では引き続き見ていきます。

## 4. なぜ iOS と Mac で「色」がズレないのか ── 作っている側の話

今回の更新と並行して、内部構造の整理を進めました。iOS では、撮影、編集、書き出し、Look、Optics (レンズ的な調整)、Source Profile (素材ごとの初期値) を、機能ごとに分けて整理しています。Mac でも、macOS 純正のアプリとして、プレビュー、通常書き出し、静止画書き出しに同じ考え方を通しました。

このとき、ひとつだけ徹底していることがあります。

**iOS と Mac で、色そのものの決め方は絶対に別物にしない。**

「iPhone で見た色と Mac で見た色が違う」── これは作品にとって致命的で、絶対に避けたい現象です。

iOS / Mac の Filmtone は、どちらも Apple 純正の Swift で書かれた native アプリです。撮影と書き出しは AVFoundation、グレーディング処理は Core Image (Apple の GPU 画像処理の仕組み)、画面は SwiftUI と AppKit。「その場の処理の質」が出るところは、各 OS が一番速く・一番きれいに動かせる方式に任せています。

ただし、色そのものの決め方 ── どの Look がどんな curve や LUT を持つか、処理をどの順序で積むか ── これを iOS と Mac でそれぞれ Swift で書くと、必ずどこかでズレが入ります。

なので Filmtone では、色のロジックを共通の TypeScript で書いた 1 つの core にまとめ、そこから Swift コードを **自動生成** しています。iOS と Mac の native アプリは、その自動生成された同じコードを参照する。

色は一箇所にまとめる。処理の質感は各 OS に任せる。── 作品としての一貫性と、ネイティブの速さ。両方を捨てないための作りです。

なお、初期の Filmtone はブラウザ上の描画エンジン (WebGPU / WebGL) を iOS / Mac に持ち込む形で始まりました (iOS 版では React と Capacitor を経由)。この描画エンジンは紹介ページなど Web 側にいまも残っていますが、shipping アプリの runtime はすでに native Swift に移っています。

作っている側としては、このくらい細部にうるさいほうが、ちょうどいいのだと思います。
