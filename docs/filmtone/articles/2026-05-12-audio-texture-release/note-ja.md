# Filmtoneの次の更新では、音声と細かい輪郭の見え方を見直しています

Status: candidate draft. Do not publish until Desktop public `1.7` and iOS
public `1.9` are both confirmed by truth scripts.

Publication switch:

- Before public truth: keep `次の更新では`, `公開後`.
- After public truth: change title to
  `Filmtoneの新しい更新では、音声と細かい輪郭の見え方を見直しました` and
  first line to `Filmtone Desktop 1.7 と iOS 1.9 を公開しました。`

---

Filmtone の次の更新では、Desktop と iOS の両方で、書き出した動画ファイルに残るもの ── 音声と、細かい輪郭の見え方を見直しています。

中心になる変更は 2 つです。

- 通常の動画書き出しで、元の素材に音声がある場合は、出力した MP4 にも音声を残す。
- `Texture Softness` / `質感のやわらかさ` という調整を追加し、細かい輪郭や局所コントラストの強さを少しだけ動かせるようにする。

新しい画面を大きく足す更新ではありません。書き出したファイルをあとで見返したときに気になる部分を直すための更新です。Filmtone は色を決めるアプリですが、最後に残るのは編集画面ではなく、保存した動画ファイルです。そこに音が残っているか、細かい輪郭が強く出すぎていないかを、今回は見直しました。

## 1. 通常の動画書き出しで音声を残す

Desktop と iOS の通常の動画書き出しで、元の素材に音声がある場合は、その音声を出力ファイルにも残すようにしています。iOS では、アプリ内で録画したクリップにもマイク音声を含める方向です。

今回大事にしたのは、書き出し処理の途中で「音声を書き込む準備をしたから大丈夫」と見なさないことです。書き出しが終わったあと、完成した MP4 をもう一度開いて、本当に音声トラックが残っているかを確認するようにしています。

プレビューで音が聞こえることと、書き出したファイルに音が残っていることは別の話です。利用者が最後に使うのは完成したファイルなので、Filmtone 側でも、完成したファイル自体を直接見るようにしました。

ハイライト書き出しは、いまの設計では音声なしのままです。今回はすべての書き出しで音が残る、という更新ではありません。まずは通常の動画書き出しで、音声付き素材を音声付きの完成ファイルとして扱うところを整えています。

## 2. Texture Softness で細かい輪郭の強さを調整する

もうひとつの変更は、`Texture Softness` です。iOS では `質感のやわらかさ` として見える予定の調整です。

これは、画面の中心も含めた細かい輪郭や、センサーや圧縮で生まれやすい局所コントラスト ── つまり「くっきりしすぎる部分」── を、少しだけ弱めるための軸です。

似た名前の `Lens Softness` とは役割が違います。`Lens Softness` は、レンズの周辺やフォーカスの落ち方に近い柔らかさを足す調整です。`Texture Softness` は、画面全体にある細かい輪郭そのものの強さを扱います。

くっきり撮れた動画は見やすい一方で、色を作り込んでいくと、細い輪郭だけが強く残ることがあります。たとえば髪、布、葉、細かい文字、夜のノイズが乗った部分です。色全体のバランスは取れているのに、そこだけ妙にシャープに見える、という感覚です。

ただし、普通の blur (ぼかし) をかけたいわけではありません。文字や髪までぼやけてしまうと、ただ解像感が落ちたように見えるだけです。やりたいのはピンぼけではなく、細かい輪郭の主張だけを少し弱めることでした。

そのため `Texture Softness` は、画面全体を均等にぼかすのではなく、細かい輪郭の成分 (detail layer) だけを取り出して、強い輪郭はなるべく残しながら、細部の出すぎを抑える方向にしています。素材情報から、輪郭が強く立ちやすそうだと分かる場合は、控えめな初期値 (source detail bias) も足します。

ただし、この素材ごとの控えめな初期値は、保存した Look には焼き込みません。素材ごとの補正を Look に入れてしまうと、その Look を別の素材に当てたときに、撮影時の補正まで一緒に持ち運ばれてしまうからです。Look はできるだけ持ち運びやすくし、素材ごとの補正は runtime (実行時) 側で扱う方針です。

効き方は素材によって変わります。`Texture Softness` は、すべての素材を自動で良くする機能ではなく、輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として見てもらうのが近いです。

## 3. iOS と Desktop で色の考え方を分けない

今回の更新は、内部構造の整理ともつながっています。

iOS では、撮影、編集、書き出し、Look、Optics (レンズ的な調整)、Source Profile (撮影素材ごとの初期値) まわりを、機能ごとに分けて整理しました。Desktop でも、macOS 純正のアプリとして、プレビュー、通常の動画書き出し、静止画書き出しで、同じ考え方を使えるようにしています。

ただし、各 OS 純正の仕組みに寄せていくことは、iOS と Desktop で色の考え方そのものを別物にする、という意味ではありません。

最初の Filmtone は、ブラウザ上で動く描画エンジン (WebGPU / WebGL) と、iOS / Desktop で共有している TypeScript の色ロジックから始まりました。iOS の初期版が React と Capacitor (Web 技術を iPhone アプリの中で動かす仕組み) を使っていたのも、その描画エンジンを iPhone に持ち込むための合理的な選択でした。

その後、撮影、Live Look、書き出しのように、その場の処理の質が直接出るところは、Apple 純正の撮影・編集まわりの仕組み (AVFoundation) と、画面構築の仕組み (SwiftUI) に降りる必要が出てきました。Web を捨てた、という話ではありません。

今の方向は、色の決め方そのものは iOS と Desktop で共有しているコア部分 (shared core) に置いて、撮影や書き出しのように OS 純正の仕組みが効くところだけ、それぞれのプラットフォームに任せる、という形です。Filmtone は、そこに寄せています。

## 公開後に試してほしいところ

公開後に試すなら、まずはいつもの Preset (curve や grade の土台) や Look (Stone / Urban Creative LUT Pack や、保存済みの仕上がり) を選び、音声付きの素材を通常の動画として書き出してみてください。次に、Advanced にある Texture Softness / 質感のやわらかさを少しだけ上げて、細かい輪郭の見え方がどう変わるかを見てください。

繰り返しになりますが、効き方は素材によって変わります。すべての素材を自動でいい感じにする機能ではなく、輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として捉えてもらえると、外れにくいです。

地味な更新だと思います。でも、動画は最後に書き出したファイルで判断されます。音が残っているか、細かい輪郭が強く出すぎていないか ── そういう、表に出にくいところも、Filmtone では見ていく予定です。

作っている側としては、こういう細部に少しうるさいくらいで、ちょうどいいのかもしれません。
