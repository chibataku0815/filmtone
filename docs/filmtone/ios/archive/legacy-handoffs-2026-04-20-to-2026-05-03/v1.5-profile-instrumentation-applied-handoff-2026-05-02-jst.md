## 適用済み変更

`OSSignposter` ベースで per-frame の 5 種類 macro signpost を export pipeline に挿入。

| signpost name | 場所 | 計測対象 |
|---|---|---|
| `decode` | videoQueue callback 内 (L849, L864) | `videoOutput.copyNextSampleBuffer()` 1 回分 — VideoToolbox decode |
| `wait-encoder` | `appendVideoSample` L2189 | `waitUntilReadyForMoreMediaData(...)` — H.264 encoder backpressure |
| `build-graph` | `appendVideoSample` L2204 | `renderableImage(...)` — CIImage chain 構築のみ(GPU 仕事は走らない、~0ms 期待) |
| `render` | `appendVideoSample` L2219 | `ciContext.render(...)` — **★ grade pipeline 本体の GPU 仕事** |
| `append` | `appendVideoSample` L2229 | `adaptor.append(...)` — encoder enqueue |

subsystem = `com.chibatakumi.film.lab.export`、category = `frame`。Instruments の `os_signpost` lane で同 subsystem/category の interval を可視化できる。

## v1.5.1 方針決定木(profile 結果から)

| 観測 | 着手対象 |
|---|---|
| `render` 支配 + Core Image lane で `GlowFamily` 系 kernel が高 | **MIP blur chain 削減**(bloom 6 / halation 6 / diffusion 4 levels の妥当性検証)、または kernel fusion(複数 CIColorKernel を 1 つに合体)、最終手段で Metal compute kernel 移植 |
| `render` 支配 + 他 sub-stage が高 | 該当 kernel 単独最適化(BaseGrade v2 の 3-piece curve / Vignette ray-angle math 等) |
| `wait-encoder` + `append` が支配 | H.264 encoder bitrate 設定見直し(現行 1080p で何 Mbps?過大なら下げる)、または `AVAssetWriterInput` の `expectsMediaDataInRealTime`/`mediaDataLocation` チューニング |
| `decode` が支配(仮説外) | `VTDecompressionSession` 直結検討、`AVAssetReaderTrackOutput` の output settings 確認(現行 ProRes → BGRA / 420YpCbCr10BiPlanarVideoRange の format conv コスト) |
| `build-graph` 非ゼロ | `applyGrade` 内に eager evaluation が紛れている bug。特に `cgImage` / `extent` 触れる箇所を疑う |

## 範囲外(本 PR では着手しない、v1.5.1+)
