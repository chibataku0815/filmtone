---

Filmtone は、iPhone と Mac で動画の色味を整えるためのアプリです。iPhone 側 (Filmtone iOS) は、撮影、色の調整、質感のある動画として書き出しまでを、1 台の iPhone の中で進められます。

iOS 1.9候補では、`Texture Softness` / `質感のやわらかさ` という、細かい輪郭やディテールの見え方を整えるための新しい調整を入れています。あわせて、通常の動画書き出しで音声が出力されない不具合と、アプリ内で録画したクリップでマイク音声が含まれない不具合を直しました。

最後に保存した動画を見返したときに、髪や葉、細かい文字の輪郭が強く出すぎていないか、という部分を見直すための調整です。音声まわりは、もともと残るはずだったところで残っていなかったので、直しました。

## 1. Texture Softnessで、細かい輪郭の見え方を調整する

今回の更新で新しく入れた調整が、`Texture Softness` です。iOS では「質感のやわらかさ」として見える予定の調整です。

これは、画面全体をぼかすための機能ではありません。細かい輪郭や、センサー・圧縮・シャープネス処理で強く見えやすい局所コントラストを、少し弱めるための軸です。

`Lens Softness` とは役割が違います。`Lens Softness` は、レンズや周辺の柔らかさに近い調整です。`Texture Softness` は、画面の中心も含めた細かい輪郭や質感の出方を扱います。

最近の iPhone やアクションカメラの素材は、撮影時にカメラ側 (センサーや内部の画像処理) が細かい輪郭を強めに見せる sharpening を、撮って出しの段階で焼き込んでいます。Filmtone 側で色を整えても、その焼き込まれたシャープさ自体は減りません。色全体のバランスが取れたあとに、もともと立っていた細い輪郭だけが目立って見える、ということが起きます。たとえば、髪、布、葉、細かい文字、夜のノイズのような部分です。

ただ、普通の blur (ぼかし) をかけたいわけではありません。文字や髪までぼやけると、ただ解像感が落ちたように見えます。やりたいのはピンぼけではなく、細かい輪郭の主張を少し弱めることです。

そのため `Texture Softness` は、単純なぼかしではなく、細かい輪郭の成分 (detail layer) を見て、強い輪郭はなるべく残しながら、細かいディテールの出すぎを抑える形にしています。

撮影機種やカラープロファイルなど、素材情報が分かる場合は、控えめな素材別の補正 (source detail bias) も足します。ただし、この補正は保存した Look には焼き込みません。Look は素材をまたいで使うものなので、撮影素材ごとの補正を保存済み Look の中に混ぜないようにしています。

このあたりは、まだ素材ごとの調整余地があります。1.9候補では、「細かい輪郭の見え方を調整するための新しい軸を追加した」更新として見てもらうのが近いです。

## 2. 通常の動画書き出しと録画クリップの音声を直しました

1.9候補では音声まわりで 2 点直しています。

ひとつは、アプリ内で録画したクリップにマイク音声が含まれない場合があった点。もうひとつは、通常の動画書き出しのときに、元の素材に音声があっても、書き出したファイルに音声が残らない場合があった点です。

内部では、書き出しが終わったあとに完成ファイルをもう一度開いて、音声トラックが残っているかを確認するようにしています。書き出し中の状態だけでは「音声が無事に書けたか」が判定できないことがあったので、完成ファイル自体を直接見るようにしました。

ハイライト書き出しは、今回の範囲では音声なしの設計のままです。今回の修正は、通常の動画書き出しと録画クリップの範囲です。

## 3. 公開後に試してほしいところ

まずはいつもの Look (`Stone` のようなフィルム系、`Urban Creative` のような街並み系、自分で保存した仕上がりなど) を選んだうえで、`Texture Softness` / `質感のやわらかさ` を少しだけ上げてみてください。髪、布、葉、細かい文字、夜のノイズがある素材だと、輪郭の見え方の違いを判断しやすいです。音声付き素材を通常の動画として書き出した場合は、完成ファイルに音声がそのまま残ることもあわせて確認できます。

効き方は素材によって変わります。すべての素材を自動でよくする機能ではありません。輪郭が強く見えすぎる素材に対して、調整の選択肢をひとつ増やす更新として使ってもらうのが近いです。

かなり細かい更新です。でも、動画は最後に保存したファイルで判断されます。音が残っているか。輪郭が強く出すぎていないか。Filmtone では、そういう少し地味なところも見ていきます。

## 4. 作っている側で考えていること

少しだけ実装寄りの補足です。使うだけなら読み飛ばして大丈夫です。

今回の更新を入れるために、iOS アプリの内部も整理しました。撮影、編集、書き出し、Look、Optics (レンズ的な調整)、Source Profile (撮影素材の色の読み方) まわりを機能ごとに分け、巨大な Swift ファイルに寄りすぎていた部分を分解しています。動画アプリは一度動いたら終わりではなく、撮影、プレビュー、書き出し、保存後の見直しまで少しずつ詰める必要があるので、その土台を作っています。

iOS の Filmtone は、Apple 純正の Swift で書かれた native アプリです。撮影と書き出しは AVFoundation、色のグレーディング処理は Core Image (Apple の GPU 画像処理の仕組み)、画面は SwiftUI、という構成です。Mac の Filmtone も同じ考え方で native の macOS アプリとして書かれています。

iOS と Mac で色の決め方を別物にしているわけではありません。どんな Look がどんな処理を持つか、どの順序で処理を積むか、といった「色の決め方」そのものは、TypeScript で書いた共通の core に置き、そこから Swift コードを自動生成して両方のアプリが参照する形にしています。色は 1 つの正本を共有して、撮影や書き出しのように「その場の処理の質」が出る部分は各 OS の native の仕組みに任せる、という方針です。

なお、初期の Filmtone はブラウザ上の描画エンジン (WebGPU / WebGL) を React + Capacitor 経由で iPhone に持ち込む形で始まりました。いまもこの描画エンジンは残っていて Web 側の紹介ページなどで使われていますが、iOS / Mac の shipping アプリの runtime はそこから native Swift に移っています。

作っている側としては、このくらい細かいところを気にするアプリでいたいです。
