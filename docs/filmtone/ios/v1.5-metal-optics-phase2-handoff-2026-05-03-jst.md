## Phase 2 段階 2 EdgeOptics Metal — 何を試して何が起きたか

### 設計

- 新 Metal kernel 4 個を `FilmtoneMetalOpticsRenderer.swift` の inline source に追加:
  - `filmtoneRadialRGBSplit` (CIKernel `radialRGBSplit` のポート)
  - `filmtoneSeparableGaussianH` / `filmtoneSeparableGaussianV` (CIGaussianBlur 置換、`sigma = inputRadius`、tap 数 `2*ceil(3σ)+1` 上限 32)
  - `filmtoneEdgeSoftnessBlend` (CIKernel `edgeSoftnessBlend` のポート)
- `EdgeOpticsFrameParams` / `OpticsChainParams.edgeOptics` 拡張。
- `applyEdgeOpticsStage` に Metal gate を追加し、成功時は `edge → glow → vignette` を 1 Metal pass で処理 (Phase 2.b の handoff 1 回方針)。
- frame-scope flag (`metalEdgeOpticsAppliedThisFrame` / `metalGlowAppliedThisFrame`) で applyGlowFamilyStage と applyVignetteStage の二重適用を防止。
- sidecar `acceleratedRenderStages` に `"EdgeOptics/metal"` を追加。

### 実測

- exportElapsedMs **139,890 ms (140s)**、avgRender/frame 34.87ms、buildGraphMs 5,084ms。
- `acceleratedRenderStages` **不在**。
- thermal nominal→nominal、lowPower false。

### 解釈

- `acceleratedRenderStages == nil` かつ `buildGraphMs` が Full CI baseline 並み (5s) → **両 Metal gate (applyEdgeOpticsStage / applyGlowFamilyStage) 共に entry した形跡なし**。
- 最も整合する仮説: 新 4 kernel のいずれかで Metal source compile error / function lookup error → `FilmtoneMetalOpticsRenderer.init(...)` で `return nil` → `metalOpticsRenderer` が nil → 全 Metal gate の `let renderer = metalOpticsRenderer` 条件で deny。
- ただし 140s が Full CI (193s) より約 50s 速い理由は未確定。考えられる説明:
  - 端末の thermal/cache 状態 (前 export 直後で warm)
  - 部分的に何か Metal が走っている (NSLog 確認必要)
  - decode/encode bucket が早い (decode 1.7s、append 0.7s で確かに以前より速い)
- いずれにせよ前合意の閾値「-3s 未満で打ち切り」を符号反転で大幅超過 → **即 revert** を執行。

### Revert スコープ

`FilmtoneMetalOpticsRenderer.swift` と `FilmtoneExportSession.swift` を Edit で逆向けに、段階 1 (Glow+Vignette Metal) 状態に復帰:

- sidecar の `EdgeOptics/metal` 追加分も削除。

## Decision Point: 60-70s 目標について

Glow OFF (85.7s, 画質落とし) と Glow+Vignette Metal (94.8s, 視覚同等) の差は約 9s。Vignette は -0.8s しか拾えなかった事実、EdgeOptics は実装したが gate fail で revert した事実から、**現構造 (CI 経路 + Metal optics chain で 1 handoff) では 90-95s 圏が現実下限**。

60-70s 圏は別 lane の作業:

1. **AVAssetReader → MTLTexture 直接化** (CI handoff bypass)
   - 現状の `ciContext.render(input, to: inputTexture, commandBuffer:)` の +43s overhead を削る大改修
   - decode → MTLTexture を直接、CI graph の eager render を経由しない経路
   - 別 lane / 別 chat で取り組む価値あり
2. **Mip pyramid optimization** (Glow Metal 内部)
   - 現 6 mip level × 3 plate (bloom / halation / diffusion) を融合 / 削減
   - 5-10% の render bucket 削減見込み (実測 -2-4s)
   - 段階的に取り組める small lane
3. **EdgeOptics Metal の再挑戦** (compile failure 原因究明)
   - NSLog で `library.makeFunction` / `makeComputePipelineState` のどこで nil/throw か特定
   - 4 kernel の syntax を separable Gaussian (一番疑わしい、`for (int i = -radius; ...)` の dynamic uniform branching か) から個別検証
   - 修正できれば再試行、ただし forced profile 試算は信頼できないので拾える幅は不透明
