## How To Run The Prototype Export

iOS は env var を Xcode scheme 経由で渡す必要がある（devicectl install 後の
springboard launch では env var は届かない）。

1. Xcode で `ios/App/App.xcworkspace` を開く。
2. `Product → Scheme → Edit Scheme... → Run → Arguments`。
3. `Environment Variables` に追加:
   - `FILMTONE_EXPORT_METAL_OPTICS = 1`
4. （任意）以前追加していた `FILMTONE_EXPORT_DISABLE_GLOW_FAMILY` は外す
   または `0` に。両方 ON だと Glow が完全 OFF になり Metal path には
   入らない（gate で `!disableGlowFamilyForExport` を要求しているため）。
5. iPhone を Mac に繋いで Xcode から `Product → Run`（実機 Release config
   推奨だが、scheme 上で環境変数を渡す関係で Debug でも可。
   速度比較は同じ Run 設定で揃える）。
6. 既存と同じ素材 `A001_03270631_C008.mov` で Quality export。
7. 起動時 NSLog に
   `FilmtoneExportSession: Metal optics prototype enabled by FILMTONE_EXPORT_METAL_OPTICS (Quality video only)`
   が出ているか xcrun devicesyslog or Xcode console で確認。

### What To Look For In The Sidecar

```jsonc
{
  "performance": {
    "exportElapsedMs": <number>,
    "renderMs": <number>,
    "avgRenderMsPerFrame": <number>,
    // 新フィールド: Metal が走った場合だけ生える
    "acceleratedRenderStages": ["GlowFamily/metal"]
```

`acceleratedRenderStages` が無い → gate のどれかで弾かれている（もしくは
renderer init が失敗）。NSLog で原因を確認する:
- `FilmtoneMetalOpticsRenderer: Metal device unavailable`
- `FilmtoneMetalOpticsRenderer: shader compile failed: ...`
- `FilmtoneMetalOpticsRenderer: pipeline state creation failed: ...`

## Visual Equivalence Argument

Metal 側の数式は CI kernel の **直接ポート**:

| CI Kernel | Metal Kernel | 数式一致? |
|---|---|---|
| `softKneeHighlight` (CIColorKernel) | `filmtoneSoftKneeHighlight` | ✓ 完全一致 |
| `tentDownsample` (CIKernel, 13-tap) | `filmtoneTentDownsample` | ✓ 13-tap 重み一致 |
| `tentUpsample` (CIKernel, 9-tap) | `filmtoneTentUpsample` | ✓ 9-tap 重み一致 |
| `glowComposite` (CIColorKernel) | `filmtoneGlowComposite` | ✓ shoulder + headroom 一致 |
| `weightedImage` + `addImages` | `filmtoneTentUpsampleAccumulate` | ✓ fused 1 dispatch 化 |
| mip pyramid loop | `encodeMipPyramid` | ✓ 同じ accumulation 順序 |
| `halationColor(for: hue)` | `halationColor(forHue:)` | ✓ 同 RGB lerp |
| `computeMipWeights(radius, levels)` | 同 `Self.computeMipWeights` 模写 | ✓ |

差分の余地:
- `half`(fp16) vs CI working format (`RGBAh`/fp16) — 桁落ちはほぼ等価。
- mirror addressing の境界処理は pixel-space 手書きで CI の
  `mirrorCoord` と同等の結果（同じ折り返し式）。
- bilinear interpolation は手書き（Metal `texture2d::read` のみ使用、
  sampler を使わずに 4-tap 加重）。CI 側も同じ 4-tap だが内部実装で
  わずかな丸めが違う可能性あり → 視覚上は識別不能。

A/B 確認は実機 export 後に同フレーム (0%, 25%, 50%, 75%, highlight-heavy)
で並べる。代表素材 `A001_03270631_C008.mov` は強光源あり（Quality export
の bloom が出やすい）ので適切。

## Remaining Visual Risks

1. **Diffusion plate path**: 既存 CI は `image` (フルフレーム) を直接 mip
   blur するが、Metal 側もそうする。同じパス。✓
2. **Halation tint** は hue=0 で `#e81020`、hue=100 で `#c86010` の
   RGB lerp。Metal 側 `halationColor(forHue:)` で同じ係数を計算して
   `SIMD3<Float>` で渡す。✓
3. **Composite shoulder**: `1 - exp(-energy)` は Metal `exp` で同じ。
   highlight headroom は `floor + (1-floor) * sqrt(1-luma)` で同じ。✓
4. **Mip levels** はサイズ違いで丸めが入るので、CI と Metal で 1px ずれる
   可能性あり。視覚的には目立たないはず。
5. **clampedToExtent / cropped**: CI 側は extent 外を clamp する。Metal
   側は mirror addressing。境界数 px の僅差が出る可能性。視覚 OK の想定。

## Known Limitations Of This Prototype

- **Quality video のみ**。Speed / preview / still image / depth-on は
  全部 CI Glow path（gate で fallback）。
- **Vignette / EdgeOptics / Grain は CI のまま**。Phase 2 で同 renderer に
  追加する予定。
- **renderer init 失敗時は silent fallback**（`feedback_no_fallback_bug_hotbed`
  に少し抵触するが、これはレンダラ自体の有無の話で、画質を silent に
  下げる fallback ではない。NSLog で識別可能）。
- **A/B 静止画ダンプ機能は今回足していない**。ユーザーが full export を
  並べて目視で比較する。差が見える場合は次チャットで A/B dump 機能を
  追加（Quality export の特定フレームを画像として保存する小機能）。

## Decision Point: Phase 2 Trigger

実機 sidecar が来たら以下で判断:

| acceleratedRenderStages | export elapsed | 視覚同等? | 次手 |
|---|---:|---|---|
| `["GlowFamily/metal"]` | 95-110s | OK | Phase 2: Vignette + EdgeOptics Metal 化 (~60-70s 目標) |
| `["GlowFamily/metal"]` | 130s+ | OK | Metal 内部の dispatch overhead 調査 / mip 削減検討 |
| `["GlowFamily/metal"]` | < 100s | 視覚差あり | Metal kernel 数式比較し、丸め誤差箇所を特定 |
| 不在 | 193s | — | gate どこで弾かれているか NSLog で特定 |

Phase 2 を踏むかどうかはユーザー判断。Phase 1 単独でも 50% 削減なので
出荷可能性は十分ある。
